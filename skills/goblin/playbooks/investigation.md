# Investigation

Read-only. Output is a cited answer or recommendation, not code.

1. `how` skill for runtime/structure questions. For "why was it built this way" → `git log -S`, `git blame`, linked PRs/issues; cite each.
2. Answer shape: Overview, Key Concepts, How It Works, Where Things Live, Gotchas (drop empty ones). Decision between options → recommendation + tradeoffs table.
3. Cite `file:line` or commit for each claim. Label inferred vs measured.
4. `unslop` the reply.

Leads to a code change → say so and switch to `feature` or `bug-fix`.

**Reply:** the answer. For "are we sure?" give real judgment and push back if premise is wrong.
